# DSH VS Code 插件设计规格

- 日期：2026-08-15
- 状态：已与用户逐节确认，待用户最终审阅
- 范围：纯 VS Code 扩展（不涉及 DSH 本体代码）

## 1. 背景与目标

DeepSeek Harness（DSH）的浏览器界面目前需要手动在终端运行 `dsh web` 并切换到外部浏览器使用，在 VS Code 等 IDE 中配合使用不便。

**目标**：开发一个 VS Code 扩展，安装后点击插件图标即可在 VS Code 侧边栏内直接使用 DSH 的 web 页面，服务启动、端口发现等杂事全部由插件自动处理。

**范围锁定（用户已确认）**：本期只做纯 VS 插件，不开发、不修改 DSH 本体代码。插件只依赖 DSH 的稳定公开接口（`dsh web` 命令 + HTTP 端口）。深度双向联动（如选中代码发给 DSH、DSH 修改建议应用到编辑器）属于二期，本期架构为其预留接缝。

## 3. 可行性预研结论

对已安装的 DSH（0.1.0-rc.6）实际检查确认：

1. `dsh web` 默认监听 `127.0.0.1:3080`，支持 `--port`（传 0 由系统分配随机端口）。
2. `/api` 存在 browser-trust 栅栏：要求请求 Host 为 loopback 或受信任 LAN 地址，且浏览器请求的 Origin 与 Host 同源。VS Code webview 中 iframe 加载 `http://127.0.0.1:3080` 时 Origin 与 Host 同源，**可正常通过校验**。
3. 前端静态服务未设置 `X-Frame-Options` 或 CSP `frame-ancestors`，**页面允许被 iframe 嵌入**。
4. DSH web 前端无登录逻辑（凭据由服务端读取 `~/.dsh/.credentials.yaml`），webview 内嵌无登录障碍。webview 与外部浏览器的 localStorage 不共享（欢迎提示、会话选择等 UI 状态各自独立），影响可接受。
5. DSH 主仓库当前无任何 VS Code 扩展相关代码。

## 4. 工程基础决策

### 4.1 命名与标识

- 显示名：`DSH`
- 工程目录名：`dsh-vscode`（代码独立存放于本地，Git 后定）
- Extension ID：`dsh.dsh-vscode`
- 命令前缀：`DSH: `（如 `DSH: 打开面板`、`DSH: 重启服务`）

### 4.2 技术栈

- TypeScript + 官方 VS Code Extension API
- 打包：esbuild；发布：vsce 打成 `.vsix`
- 面板内不引入任何前端框架：主体是 iframe，外围只有一层轻量占位页（加载中/错误/重试）
- 单元测试：Node 内置 `node:test`

### 4.3 配置项（VS Code 设置，`dsh.*`）

| 配置项 | 默认值 | 说明 |
|---|---|---|
| `dsh.port` | `3080` | 期望端口（探测与启动共用） |
| `dsh.autoStart` | `true` | 未运行服务时是否自动启动 |
| `dsh.stopOnExit` | `true` | 关闭最后一个窗口时是否停止插件启动的服务 |
| `dsh.host` | `127.0.0.1` | 服务地址；仅允许 loopback 值（`127.0.0.1` / `localhost` / `[::1]`），非法值回退默认 |
| `dsh.extraArgs` | `[]` | 启动 `dsh web` 时附加参数（如 `--trusted-host`） |

### 4.4 平台

Linux / macOS / Windows 三平台兼容（Windows 调用 `dsh.cmd`，处理路径空格等）。

## 5. 整体架构与模块划分

```
dsh_vs/
├── package.json                # 扩展清单：图标、视图容器、命令、配置项
├── package.nls.json            # 默认英文文案
├── package.nls.zh-cn.json      # 中文文案
├── src/
│   ├── extension.ts            # 入口：装配各模块，注册图标/面板/命令/状态栏
│   ├── config.ts               # 读取 dsh.* 设置项并监听变更
│   ├── i18n.ts                 # 动态文案字典，按语言规则选词
│   ├── service/
│   │   ├── detect.ts           # 端口探测：发 HTTP 请求判断 dsh web 是否就绪
│   │   ├── process.ts          # 子进程封装：跨平台启动/停止 dsh web，捕获日志
│   │   └── manager.ts          # 服务管理器（核心）：状态机 + 编排
│   ├── panel/
│   │   ├── provider.ts         # WebviewViewProvider：iframe + 占位页切换 + 按钮转发
│   │   └── html.ts             # 占位页 HTML 模板（纯模板，无逻辑）
│   └── statusbar.ts            # 状态栏项：状态显示 + 点击开关面板
└── assets/                     # 图标
```

### 5.1 服务管理器状态机

```
idle ──点击图标──▶ detecting ──有响应──▶ ready（复用已有服务）
                       │
                       └──无响应──▶ starting（拉起 dsh web 子进程）
                                       │
                                       ▼
                                   waiting（轮询 0.5s/次，最长 15s）
                                       │
                              ┌─就绪──┴──超时─┐
                              ▼              ▼
                           ready          failed（面板显示原因+重试）
                              │
                   用户点"停止"/窗口关闭
                              ▼
                           stopping ──▶ idle
```

### 5.2 三个关键设计点

1. **面板与服务管理器解耦**：面板只负责"显示网址"，通过消息机制向管理器索取 URL；管理器不知道面板的存在。将来加编辑器 Tab 模式、外部浏览器等消费方时不动管理器。
2. **iframe 加载真实 DSH 网页**：插件与 DSH 之间无自定义协议，DSH 升级/换端口不影响插件逻辑。
3. **日志走 VS Code 输出通道**（Output Channel），不在终端弹窗，面板"日志"按钮一键查看。

## 6. 组件职责与数据流

### 6.1 职责

| 组件 | 职责一句话 | 依赖 |
|---|---|---|
| `extension.ts` | 装配：注册图标、面板、命令、状态栏、配置监听 | 所有模块 |
| `config.ts` | 读取 `dsh.*` 设置项并监听变更 | VS Code 设置 API |
| `service/detect.ts` | 发一个 HTTP 请求，判断服务是否就绪（识别"有响应但不是 DSH"） | 无 |
| `service/process.ts` | 跨平台拉起/停止 `dsh web` 子进程、捕获输出 | 无 |
| `service/manager.ts` | 状态机：探测→复用/启动→等待→停止；对外只暴露"状态订阅 + getUrl() + 控制命令" | detect、process |
| `panel/provider.ts` | 管理侧边栏面板：加载/错误/网页三态切换，转发面板按钮事件 | manager |
| `panel/html.ts` | 生成占位页 HTML（纯模板） | 无 |
| `statusbar.ts` | 状态栏项：显示状态、点击开关面板 | manager |
| `i18n.ts` | 动态文案字典，按语言规则选词 | 无 |

### 6.2 三条主线数据流

1. **打开面板**：点击图标 → VS Code 创建面板视图 → provider 向 manager 要 URL → manager 走状态机 → 就绪后把 URL 发给面板 → iframe 加载。期间面板始终显示"正在启动 DSH 服务…"动画页，任何路径不白屏。
2. **状态变化推送**：manager 状态单向广播 → 状态栏更新 → 面板（若打开）同步切换界面。状态唯一源头是 manager，下游只订阅。
3. **面板按钮 → 控制命令**：按钮点击 → 消息给 provider → 转成对 manager 的命令（重启/停止/复制URL/外部打开/日志）。面板永不直接碰进程。

### 6.3 二期预留接缝

`manager` 暴露的 `getUrl()` 与状态订阅即二期 DSH 插件的挂载点；二期新增"桥"模块即可，不动现有组件。

## 7. 错误处理与边界情况

### 7.1 服务类异常

| 场景 | 插件行为 |
|---|---|
| 端口被其他程序占用 | 探测识别"有响应但不是 DSH"；面板提示端口被占，给"换端口重试 / 打开设置"按钮，不强行杀他人进程 |
| `dsh` 命令不存在 | 启动前检查命令可用性；面板显示"未找到 dsh 命令"及安装指引 |
| 启动 15 秒未就绪 | 判失败，面板显示失败原因（读取子进程日志）+ 重试按钮；状态栏红色"启动失败" |
| 运行中服务突然退出 | manager 捕获子进程退出事件，广播状态；面板自动切"已断开"，一键重启 |
| 用户改 `dsh.port` 设置 | 监听变更：若插件自启服务在跑，自动重启到新端口；面板刷新 |

### 7.2 界面类异常

| 场景 | 插件行为 |
|---|---|
| 点图标时服务未就绪 | 面板显示加载动画页（非白屏），就绪后自动切换 |
| iframe 加载失败 | 捕获加载错误，显示"无法加载页面"占位页 + 重试按钮 |
| 面板关闭而服务继续运行 | 正常行为（全局单实例，服务保持运行） |
| 多 VS Code 窗口 | 每窗口各自有面板，共享同一服务；状态同步（同一 manager 广播） |

### 7.3 进程与资源

| 场景 | 插件行为 |
|---|---|
| VS Code 崩溃/被强杀 | 子进程"父进程退出即自杀"（detached + 父子钩子），不留僵尸 |
| 插件启动 vs 手动启动 | 记录"谁启动的"；退出时只停止插件自己启动的，手动启动的永不干预 |
| Windows | 调用 `dsh.cmd`、处理路径空格、探测与日志跨平台 |
| 重复点击/连续触发 | 状态机保证同时只有一个启动流程，不会拉起两个服务 |

### 7.4 安全边界（明确不做的事）

- 只连接 loopback 地址（`127.0.0.1` / `localhost` / `[::1]`），不尝试局域网/远程地址（防钓鱼与远程代码执行暴露）；`dsh.host` 设置项做同样校验。
- 不读取、不传输 `~/.dsh` 下任何凭据文件。
- iframe 固定同源加载，不向 DSH 网页注入任何脚本。

## 8. 图标与侧边栏（含右侧辅助侧边栏）

### 8.1 VS Code 平台规则说明

VS Code 不允许插件编程式地把图标钉死在右侧辅助侧边栏；视图放在哪一侧由用户决定（拖动视图标题，或命令面板 "Move View"）。此为平台规则，所有插件一致，插件不可绕过。

### 8.2 实现方式

1. **左侧活动栏图标（默认即有）**：注册视图容器 `dsh`（图标），点击即在侧边栏显示 DSH 面板。
2. **右侧辅助侧边栏图标（一次移动，永久生效）**：用户将 DSH 视图移到右侧辅助侧边栏后，右侧栏顶部出现 DSH 图标，点击同样打开面板；VS Code 记住位置，重启后保持。
3. **引导**：
   - 新增命令 `DSH: 在辅助侧边栏打开`：执行时聚焦辅助侧边栏；若视图尚未移到右侧，弹一次性引导提示（VS Code 通知 + 面板内提示两种形式，i18n 双语），告知拖动视图或使用 "Move View" 的方法。
4. **两侧图标并存**：视图移到右侧后，左侧活动栏图标依然存在（点击聚焦右侧面板），实现"左侧图标 + 右侧图标"都可用。

**取舍说明**：不强塞两个重复面板（一个容器放两个相同 webview 视图会造成混淆），用"单视图 + 位置记忆 + 一次引导"达到双侧效果。

## 9. 多语言（i18n）

- **判定规则**：取 VS Code 显示语言 `vscode.env.language`；`zh-*` 开头 → 简体中文；其余任何语言 → 英文。
- **静态文案**（命令名、图标名、设置项描述）：`package.nls.json`（默认英文）+ `package.nls.zh-cn.json`（中文），VS Code 按自身语言自动选用。
- **动态文案**（状态栏、加载页、错误提示、面板按钮、输出通道日志）：`src/i18n.ts` 字典 + `t(key)` 按上述规则选词。
- **DSH 网页本身语言**：不在插件控制范围，保持原样。

## 10. 测试与验收

### 10.1 测试策略

**① 单元测试**（`node:test`，不依赖真实 DSH，用假探测/假进程）
- 服务管理器状态机全部分支：就绪、超时、失败、崩溃、重复点击，断言状态走向。
- i18n 规则：`zh-*` 出中文、其余出英文。
- 配置读取与默认值。

**② 集成测试**（依赖真实 DSH）
- 真实 `dsh web --port 0` → 验证探测、复用、停止流程。
- 模拟服务中途被杀 → 验证断开检测与重连。

**③ 人工验收清单**

| # | 验收项 | 通过标准 |

| 1 | 安装 .vsix 后左侧活动栏出现 DSH 图标 | 图标可见、可点击 |
